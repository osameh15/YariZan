# ADR-0006 — Browser authorization and desktop-only provisioning

Status: Phase 3 implementation, independent review required; commercial enrollment remains blocked.

Preflight: PR #2 merged at `e7af35f1771c7d85277aea338a26c957176adb85`; latest main CI [38703949800](https://github.com/osameh15/YariZan/actions/runs/38703949800) completed successfully before source changes. No pending main run was found. Work uses a clean `YariZan-Web` worktree on `feat/yarizan-v2-nuxt-portals`; original untracked brand files are preserved. Graph service/coverage returned Transport closed, so source inspection is authoritative.

Implementation sequence: (1) split provisioning and test backend authority; (2) Nuxt 4 strict foundation, local assets, same-origin constrained proxy and typed contracts; (3) Persian storefront/customer and MFA Admin portals; (4) CNG/DPAPI WPF provisioning and real C# interoperability; (5) Playwright/security/Windows regression, screenshots and report. Commit focused checkpoints; never deploy or merge.

The browser receives only a public receipt. A key-proof-created pairing has a five-minute browser approval code, stable device anchor, account generation and optional existing owner. The desktop displays the code; the Connect URL contains no secret. Browser preview requires the code in a POST body. Browser claim authorizes one account/profile and chooses the initial password; it never signs or returns an enrollment, device bearer or desktop claim grant. Existing-owner cookie plus CSRF is mandatory for another profile. Nonlocking admission precedes Argon2id; the final transaction rechecks generation, owner, state, expiry and code.

Only a fresh CONFIRM challenge bound to the pairing and exact key/fingerprint can pick up enrollment. Pending pickup returns only PENDING; approved pickup atomically creates the profile once and returns the existing ADR-0004 enrollment plus a 15-minute bearer. Lost responses are recovered by a new challenge: business issuance is idempotent but bearer rotation is fresh. A used challenge cannot replay. An approved profile may recover its certificate and renew a bearer through fresh AUTH proof after restart. Browser cookies/codes alone never authorize these routes. Pairing IDs may be persisted locally; private keys never leave CNG. Desktop verifies pinned roots, key digest, machine/fingerprint before atomic DPAPI storage. Cached paid/trial process access never depends on bearer renewal.

Legacy claim/register/desktop-confirm credential delivery is retired, rather than keeping two active protocols. Old pending pairings are invalidated by the additive migration. Customer reset invalidates pending approvals, and issuance compares captured generation to the current device generation. Account, profile and trial budgets remain machine-wide per generation/SKU/allocation epoch.

Nuxt proxies only an explicit set of browser-facing API routes to a configured loopback/container backend. Desktop challenge/pickup/authentication routes cannot be called through the web proxy. Original Origin and CSRF validation are retained. No privileged service credential, device bearer or password is serialized into SSR payloads. Authentication pages are client-loaded and no-store; public catalog can use SSR with no cookie forwarding. Browser sessions remain HttpOnly and path /api/v2. A separate CSRF cookie contains only the synchronizer token, never the session credential, and allows reload without putting credentials in localStorage. Admin and customer CSRF/session namespaces remain separate.

This does not solve first-claim hardware assurance. An attacker-generated key plus a spoofed unclaimed fingerprint can preempt a device account. Production startup and commercial root approval remain closed pending independent assurance, disputes/support policy, external signing custody and physical Windows acceptance. No attestation, live payment, SMS, deployment or cross-ID license recovery is claimed.

Final claim approval locks and revalidates the current authorizing session after password work. Browser dialogs discard late secret responses after close or replacement. CSP uses per-render nonces. Actual Windows CNG/DPAPI provisioning is exercised together with Playwright browser approval; this is synthetic ownership evidence, not hardware attestation.

Update (automatic license activation): after a successful key-proof pickup, the desktop starts the visible payment wait on the Lock page. It uses only the existing device-authenticated `GET /api/v2/desktop/entitlements` and `POST /api/v2/desktop/licenses/pickup` routes, renews the short-lived bearer through CNG AUTH proof, and never reads browser checkout state.
